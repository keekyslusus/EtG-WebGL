# Задача: эффекты Wwise на отдельных звуках (дисторшн, флэнджер, ревербы, гармонайзер, компрессор, тремоло)

## Контекст

Приватный порт Enter the Gungeon (Unity 2017.4.27f1) в WebGL 2. Корень: `C:\Users\pooky\Desktop\vm\etg`.
Сначала прочитай `README.md` и `port/README.md` (раздел про звук там устарел: строка «No sound» в README —
неправда, звук уже есть; допиши раздел о звуке по итогам своей работы).

Wwise в браузер не переносится, поэтому звук играет собственный движок на Web Audio:

- `port/audio/wwbank.py` — разбор банков Wwise (`EtG_Data/StreamingAssets/Audio/GeneratedSoundBanks/Windows/
  Init.bnk`, `SFX.bnk`, версия банка 128 = Wwise 2017.2). Каждый объект HIRC читается до конца, несовпадение
  размера — ошибка. Эффекты — объекты `fxshareset`/`fxcustom`: `{plugin, params (сырые байты)}`;
  `parametric_eq()` и `delay()` расшифровывают параметры этих двух плагинов.
- `port/audio/build_audio.py` — собирает `ripped/ExportedProject/Assets/StreamingAssets/webaudio/`
  (`audio.json` — граф событий/узлов/шин + `effects` + `reverbs`, пакеты звука Opus, музыка) и копирует в
  `webbuild/StreamingAssets/webaudio/`. Перекодированные файлы кешируются, повторный запуск — секунды.
- `port/audio/etg-audio.js` — движок. Эффекты узлов применяет `effectChain(fx, node)` (у голоса: звук, затем
  родители по цепочке). Сейчас поддержаны только `parametric_eq` (биквады) и `delay` (линия с обратной
  связью, хвост — `effectTail`). Остальные плагины молча пропускаются. Реверберации **шин** — свёртка с
  импульсной характеристикой, измеренной в настоящем Wwise (`loadReverb`, `data.reverbs`).
- `port/audio/soundboard.html` — тестовая страница (события, переключатели, состояния, громкость):
  `http://localhost:8080/StreamingAssets/webaudio/soundboard.html` при запущенном `serve-webbuild.ps1`
  (или preview «webbuild» из `.claude/launch.json`).

### Эталон: настоящий Wwise

`port/WwiseRef` (.NET 9) грузит `EtG_Data/Plugins/AkSoundEngine.dll` игры и рендерит сценарии офлайн:
вывод «System» приостановлен (`Suspend(renderAnyway)`), импорт `QueryPerformanceCounter` в DLL подменён
виртуальными часами (`Clock.cs`) — каждый `RenderAudio()` = один кадр в 1024 сэмпла, в колонки ничего не идёт.
`--remove-fx bus:index,...` снимает эффекты с шин (`SetBusEffect`). DLL экспортирует ещё
`CSharp_SetActorMixerEffect(uint nodeId, uint fxIndex, uint shareSetId)` — то же для узлов
(звуков/контейнеров), пригодится. Пути записи — относительно папки банков (`AddBasePath` не реализован).

`python port/audio/audiodiff.py` — дифф-тест: `audiodiff_cases.py` строит кейсы из `audio.json`, WwiseRef
рендерит их, тот же сценарий рендерит `EtgAudio.render()` в headless Chrome (`audiodiff.html`), сравниваются
громкость/пик/начало/конец/спектральный центроид/баланс, отчёт `port/build/audiodiff/report.html`
(+ `report.md`, худшие кейсы с аудио для прослушивания). Опции: `--filter REGEX` (по имени кейса),
`--resume` (рендерить только кейсы без признаков в `port/build/audiodiff/features/{ref,ours}`), `--jobs N`.
Полный прогон ~25 мин; для своей работы гоняй `--filter` по затронутым событиям (удалив их файлы из
`features/ours`, если перед этим менял движок). Эталонные признаки в `features/ref` уже посчитаны — Wwise не
меняется. `port/audio/measure_ir.py` — как измерялись реверберации шин (Винеровская деконволюция по многим
кейсам «с эффектом / без», проверка на отложенных кейсах) — образец для измерения эффектов узлов.

## Что сделать

Эффекты на узлах, которые движок сейчас пропускает (41 экземпляр; эффект на контейнере действует на все звуки
под ним):

| Плагин | Экземпляров | Характер |
|---|---|---|
| Wwise Guitar Distortion | 10 | нелинейный |
| Wwise Flanger | 9 | меняется во времени (LFO) |
| Wwise Matrix Reverb | 9 | линейный |
| Wwise RoomVerb | 4 | линейный (с лёгкой модуляцией хвоста) |
| Wwise Harmonizer | 4 | сдвиг высоты (дополнительные голоса) |
| Wwise Compressor | 4 | нелинейный |
| Wwise Tremolo | 1 | меняется во времени |

Список узлов: в `audio.json` — `nodes[id].fx` = `[[index, effectId]...]`, `effects[effectId].plugin`. Какие
события до них доходят — обход от `events[*]` (действия типа 4 = Play) вниз по графу, как в
`audiodiff_cases.py`.

Подход:

1. **Линейные (Matrix Reverb, RoomVerb на звуках)** — измерить, а не моделировать: рендер событий с эффектом и
   со снятым (`SetActorMixerEffect(node, index, 0)` — добавь опцию в WwiseRef по образцу `--remove-fx`),
   деконволюция как в `measure_ir.py`, обрезка хвоста (`trim`), файл в `port/build/audio/ir/`, экспорт через
   `build_audio.py`. **Не ставь свёртку на каждый голос** (дорого): эффект линейный, поэтому голоса узла можно
   сложить в одну общую «шину эффекта» со своей `ConvolverNode` (одна на эффект-экземпляр), выход — туда же,
   куда шёл бы голос. Дорогостоящесть свёртки: ~3% ядра на 2.5 с стерео при 48 кГц.
2. **Нелинейные и модулированные** — моделировать по параметрам. Раскладка параметров плагинов (структуры
   `AkGuitarDistortionFXParams`, `AkFlangerFXParams`, `AkHarmonizerFXParams`, `AkCompressorFXParams`,
   `AkTremoloFXParams` Wwise 2017.2) — найди в документации/SDK-заголовках Wwise (веб-поиск) и сверь с
   размером блока `params` в банке (distortion 126 байт, flanger 59, harmonizer 68, compressor 22, tremolo 38;
   раскладки EQ 56 и Delay 18 уже подтверждены — см. `wwbank.py`). Затем:
   - Guitar Distortion: пре-EQ → `WaveShaperNode` по типу/драйву → пост-EQ → wet/dry;
   - Flanger: `DelayNode` с модуляцией `delayTime` от `OscillatorNode`, обратная связь, wet/dry;
   - Tremolo: `GainNode`, модулируемый LFO (глубина, частота, форма);
   - Harmonizer: дополнительные копии голоса со сдвигом `playbackRate` (это источник-буфер, поэтому так проще
     и честнее, чем гранулярный сдвиг) с их громкостью/фильтрами, плюс dry;
   - Compressor: **не `DynamicsCompressorNode`** — он в Chrome срезает транзиенты на ~10 дБ даже ниже порога
     (так был найден баг с лимитером, см. `softClipCurve` в движке). Свой расчёт усиления (огибающая по
     атаке/релизу, порог, ratio) или хотя бы проверь по дифф-тесту, что не хуже, чем без эффекта.
3. Каждое приближение проверь дифф-тестом на затронутых событиях: метрики должны стать ближе к Wwise, чем
   без эффекта (сейчас эти события в отчёте без обработки). Послушай худшие кейсы в отчёте (там WAV Wwise и
   наш рядом). Если эффект нельзя сделать лучше, чем «без эффекта», — оставь пропуск и объясни в отчёте.
4. Хвосты эффектов (реверб, флэнджер с обратной связью) не должны обрываться, когда кончается звук — см.
   `effectTail` и `Voice.finish`.

## Ограничения

- Не ломай остальное: после работы полный `python port/audio/audiodiff.py --resume` (удали
  `features/ours` перед этим) не должен ухудшиться по сводной таблице (сейчас помечено 1324 из 2063,
  уровень эффектов: медиана −0.2 дБ, p10…p90 −2.2…+3.5).
- Производительность: игра идёт в браузере; на голос — не больше пары десятков узлов Web Audio, ничего
  тяжёлого на каждый голос. Выстрелы/удары — сотни голосов в минуту.
- Код в стиле окружающего (комментарии по делу, без «tutorial»-шума). Длинные heredoc в bash здесь ломаются —
  правки делай инструментами редактирования файлов или скриптом из файла.
- Unity пересобирать не нужно: всё в `etg-audio.js` и `audio.json` (после `python port/audio/build_audio.py`).
  Unity-проект в момент работы может быть открыт — его не трогай.
- В конце: коммит, и короткий отчёт — что сделано по каждому плагину, цифры дифф-теста до/после, что не
  получилось и почему.
