# Задача: A/B-сравнение D3D11 и GLES в редакторе Unity

## Контекст

Приватный порт Enter the Gungeon (Unity 2017.4.27f1) в WebGL 2. Корень: `C:\Users\pooky\Desktop\vm\etg`.
Сначала прочитай `README.md` целиком — особенно разделы «Quick testing in Play Mode» и «Shaders».

Шейдеры игры есть только как байткод DX11. USCSandbox декомпилирует их в CG (`port/decompile_shaders.sh`),
`port/fix_shaders.py` правит под gles3, `port/apply.sh` кладёт в Unity-проект `ripped/ExportedProject`.

Уже есть дифференциальный тест `bash port/shaderdiff.sh` (`port/ShaderDiff`): каждый вариант каждого шейдера —
оригинальный DXBC против декомпилированного кода, перекомпилированного под D3D11, на WARP с одинаковыми случайными
входами. Сейчас все 3068 вариантов совпадают. То есть **декомпилированные шейдеры на D3D11 считают то же, что игра**.

Чего этот тест не видит в принципе — расхождений DX11 и GLES: код шейдера тот же, а движок на GLES подаёт другие
данные. Код игры написан под D3D, и его допущения зашиты в байткод константами. Уже найдено и исправлено в
`fix_shaders.py` (все — только после того, как проявились в игре):
- D3D рендерит в текстуру с перевёрнутой по Y проекцией, GL — нет; шейдеры игры выводят экранную позицию прямо из
  clip-позиции → на GLES вода на титульном экране была перевёрнутым белым градиентом (`fix_clip_space_flip`);
- текстуры затухания света на GLES читаются из альфы (`UNITY_ATTEN_CHANNEL a`) → ни один свет Unity не работал
  (`fix_atten_channel`);
- `unity_OcclusionMaskSelector` на GLES движок не задаёт → свет обнулялся (`fix_occlusion_selector`);
- upper-case значения `LightMode` не распознаются при компиляции из исходника (`fix_tag_case`).

Сколько таких ещё — неизвестно. Ловить их по одному в игре дорого.

## Идея

Три способа нарисовать шейдер:

```
1. Steam:               оригинальный DXBC         + движок D3D11
2. Unity, -force-d3d11: декомпилированный код     + движок D3D11   ≈ 1 (доказано shaderdiff)
3. Unity, -force-gles30: декомпилированный код    + движок GLES    ≈ браузер
```

Разница между картинками 2 и 3 на одинаковом кадре — это ровно расхождения DX11/GLES, включая неизвестные.

## Цель

Инструмент, который **без ручной игры** рисует одинаковые кадры в редакторе на D3D11 и на GLES 3.0 и выдаёт отчёт:
какие материалы/сцены отличаются, насколько, с картинками «D3D11 / GLES / разница».

1. **Галерея материалов.** Editor-скрипт: для каждого материала проекта (`Assets/**/*.mat`; плюс шейдеры без
   материалов — с параметрами по умолчанию) рисует объект с этим материалом в RenderTexture и сохраняет PNG.
2. **Снимки сцен.** Несколько реальных кадров (главное меню, Breach, первый этаж — см. Play Mode/`EtgWebPlayMode.cs`)
   при остановленном времени.
3. Прогон Unity в batchmode дважды: `-force-d3d11` и `-force-gles30`, результаты в `port/build/abtest/<api>/`.
4. Сравнение и отчёт (Markdown или HTML) в `port/build/abtest/`, с порогом и сортировкой по величине разницы.
5. Одна команда (скрипт в `port/`), которая делает всё это.

## Подсказки и подводные камни

- **Ловушка №1: правки fix_shaders.py для GLES безусловные.** `fix_atten_channel` и `fix_occlusion_selector`
  переписывают код текстом, поэтому на D3D11 эти шейдеры теперь *неправильные* (на D3D11 затухание в `.r`, селектор
  задаётся). Эталонный D3D11-прогон с ними покажет ложные расхождения. Лучшее решение — переделать эти правки в
  условные (`#if` по платформе, как уже сделано в `fix_clip_space_flip` через `!UNITY_UV_STARTS_AT_TOP`; для канала —
  можно опереться на Unity-шный `UNITY_ATTEN_CHANNEL` или `SHADER_API_GLES3`), тогда одни и те же файлы верны на обеих
  платформах. Заодно у `shaderdiff.sh` отпадёт нужда в `fix_shaders.py --d3d11` — проверь, что он остаётся чистым.
- **Рендер в текстуру.** Камеры игры рисуют в RenderTexture (Pixelator), и переворот проекции на D3D проявляется
  только там. Галерея должна рисовать в RT (в batchmode другого и нет) — так же, как игра.
- **Batchmode.** Не используй `-nographics` (нужен реальный графический девайс). В начале прогона проверь и запиши
  `SystemInfo.graphicsDeviceType`; если API не тот — прерывайся. `-logFile` в `port/build/abtest/`.
  Редактор должен быть закрыт (lockfile проекта) — попроси пользователя. Проект обычно открыт через
  `open-gles30.ps1`; в GLES-режиме Play From Boot ещё включает Graphics Emulation → WebGL 2.0 — проверь, влияет ли.
- **Детерминизм.** `_Time` и прочие глобальные параметры зафиксируй (проверь, что Unity не перезаписывает их при
  ручном `Camera.Render()`). Обязательная самопроверка: два прогона на одном API должны совпасть попиксельно (или
  почти — тогда это и есть порог шума).
- **Освещение и параметры.** Многие материалы без света или глобальных параметров дадут чёрное/пустое и ничего не
  покажут. Нужны: источник света Unity рядом (point/spot/directional — для ForwardBase/ForwardAdd), глобальные
  параметры, которые выставляет код игры через `Shader.SetGlobal*` (например `_CameraWS`, `_CameraOrthoSize`,
  `_CameraOrthoSizeX` у световых `GBuffer_LightRenderer*`; найди их — свойства, используемые шейдерами, но не
  объявленные в Properties). Возможно, стоит рисовать каждый материал с 2–3 наборами параметров.
- **Геометрия.** Квад с UV 0..1, белыми вершинными цветами и нормалями; спрайтовые шейдеры (tk2d, Brave/*) ждут
  `_MainTex` из материала. Материалы частиц/UI (Daikon Forge) — тоже квад. Пустые/невидимые результаты отмечай в
  отчёте отдельно: «одинаково пусто» — не значит «проверено».
- **Шум.** Сжатые форматы текстур на GLES могут распаковываться иначе, точность/`round`/NaN различаются —
  нужен порог и метрика (доля отличающихся пикселей, максимальная разница). Покажи в отчёте и мелкие, но сортируй.
- **Привязка к шейдеру.** В отчёте для каждого материала — имя шейдера и ключевые слова, чтобы найти код в
  `tools/uscs/out/`.
- Инструмент — исходники в `port/` (editor-скрипт можно класть в `port/UnityAssets/Editor/`, `apply.sh` копирует
  его в проект). `.gitignore` — белый список: исходники в `port/` попадут, `port/build/` — нет.
- Reversed-Z (D3D глубина 1→0, GL −1→1) уже проверен вручную: мягкие частицы платформонезависимы, смещение теней в
  ShadowCaster-проходах исправлено (`fix_shadow_bias`). Если галерея покажет проблемы с глубиной — сверься с README.

## Ограничения

- Ничего не коммить и не публиковать без явной просьбы. Файлы игры и рип защищены авторским правом, проект приватный.
- Не трогай `C:\Program Files\Unity\...`.
- `apply.sh` — только при закрытом Unity (переименовывает DLL). Копировать один `.shader` в проект можно и при
  открытом, после этого — Ctrl+R в Unity (проси пользователя). Лог редактора:
  `%LOCALAPPDATA%\Unity\Editor\Editor.log` — читай сам.
- Исправляя найденные расхождения в `fix_shaders.py`: правка должна быть no-op на D3D11 (под `#if`), после неё
  `bash port/decompile_shaders.sh`, `bash port/shaderdiff.sh` (должен остаться чистым), копирование в проект;
  допиши расхождение в README (абзац про DX11-vs-GLES в разделе «Shaders»).

## Критерии готовности

1. Одна команда прогоняет оба API и строит отчёт; явно перечислено, что не проверено и почему (пустые результаты,
   материалы, которые не удалось нарисовать).
2. Два прогона на одном API совпадают (детерминизм подтверждён).
3. Чувствительность: с временно откаченной `fix_clip_space_flip` материал воды титульного экрана (`TitleWaterShader`)
   попадает в отчёт как отличающийся; с ней — нет.
4. Найденные расхождения исправлены в `fix_shaders.py` (условно по платформе) или описаны, README обновлён.
