# Задача: дифференциальное тестирование декомпилированных шейдеров

## Контекст

Приватный порт Enter the Gungeon (Unity 2017.4.27f1) в WebGL 2. Корень: `C:\Users\pooky\Desktop\vm\etg`.
Сначала прочитай `README.md` (структура, конвейер сборки, раздел «Быстрая проверка в Play Mode»).

Шейдеры игры есть только в виде скомпилированного байткода DX11 (DXBC) внутри ассетов и бандлов. Их
декомпилирует [USCSandbox](https://github.com/nesrak1/USCSandbox) в ShaderLab/CG:
- исходники USCSandbox — `tools/src/USCSandbox` (git-клон), наши правки — `port/patches/uscsandbox-fixes.patch`;
- сборка: `dotnet build tools/src/USCSandbox/USCSandbox -c Release -o tools/uscs`;
- `bash port/decompile_shaders.sh` декомпилирует все шейдеры (272, из них 183 уникальных) в `tools/uscs/out`, затем
  `port/fix_shaders.py` правит их под gles3; `bash port/apply.sh` кладёт результат в Unity-проект
  `ripped/ExportedProject` (заменяет шейдеры-заглушки AssetRipper по имени `Shader "..."`).

Декомпилятор ошибается **классами**: одна ошибка в USCSandbox портит десятки шейдеров сразу. За 2026-10-11 найдено
и исправлено шесть таких классов (все в патче и в `fix_shaders.py`), каждый — только после того, как он проявился
в игре:
1. терялись ссылки render state на свойства материала (`Ref [_StencilVal]` → нет `Ref`);
2. `маска & float` переводился в целочисленный AND с усечённым литералом (был выключен `USILAndOptimizer`);
3. float-литералы печатались как `0.0#######`, и `1e-10` становился `0.0` → NaN;
4. DXBC `log` (это `log2`) переводился в натуральный `log`;
5. не-тождественный свизл константы (`cb0[2].xyxy`) выбрасывался, если по длине совпадал с переменной;
6. `sign()` на масках сравнения (true = −1 в DXBC) выходил с обратным знаком (`fix_shaders.py`, `fix_bool_subtraction`).

Ещё три расхождения — не ошибки декомпилятора, а разница DX11 и GLES, их правит `fix_shaders.py`
(`fix_occlusion_selector`, `fix_tag_case`, `fix_atten_channel`): `unity_OcclusionMaskSelector` на GLES не задаётся,
upper-case значения `LightMode` не распознаются при компиляции из исходника, текстуры затухания света на GLES
читаются из альфы (`UNITY_ATTEN_CHANNEL a`). Сравнение DX11 с DX11 такие вещи **не поймает** — учитывай это при
интерпретации отчёта и не принимай эти правки за ошибки.

Почти наверняка остались другие, которые проявляются там, куда ещё никто не заходил (боссы, другие этажи, оружие).
Ловить их по одному в рантайме дорого.

## Цель

Инструмент, который **без запуска игры** находит шейдеры, чья декомпиляция вычисляет не то же, что оригинальный
байткод, и по возможности — какой класс ошибки за этим стоит.

Идея: для каждого варианта (шейдер × проход × набор ключевых слов × стадия vertex/fragment):
1. взять **оригинальный DXBC** этого варианта;
2. взять **декомпилированный HLSL** того же варианта (ветка `#if ...` в `tools/uscs/out/*.shader`) и скомпилировать
   его обратно в DXBC для `vs_4_0` / `ps_4_0`;
3. прогнать оба на D3D11 (можно WARP, без видеокарты) на одних и тех же **случайных входах** — значения констант,
   интерполянты/вершинные атрибуты, текстуры со случайным содержимым — и сравнить выходы с допуском;
4. расхождения сгруппировать: шейдер, вариант, какой выход и на каких входах расходится; минимизировать
   (какая константа/текстура влияет).

## Подсказки и подводные камни

- **DXBC оригинала.** USCSandbox сам достаёт блобы программ из сериализованного шейдера (см.
  `tools/src/USCSandbox/USCSandbox/Processor/ShaderProcessor.cs`, `SerializedProgramInfo`, `BlobManager`; в
  `decompile_shaders.sh` удаляются `dbg_*.bin` — похоже, USCSandbox умеет их сбрасывать). Удобнее всего добавить в
  USCSandbox режим, который рядом с `.shader` пишет для каждого варианта сырой DXBC + JSON с раскладкой cbuffer'ов,
  текстур и входов/выходов (имена, слоты, смещения). Эта раскладка нужна, чтобы подать одинаковые данные в обе версии.
  Unity добавляет к DXBC свой заголовок — найди, где начинается `DXBC`.
- **Компиляция декомпилированного кода.** Это CG с макросами Unity (`UNITY_SAMPLE_TEX3D_SAMPLER`, `unity_ObjectToWorld`,
  `_LightColor0`…). Инклуды: `C:\Program Files\Unity\Hub\Editor\2017.4.27f1\Editor\Data\CGIncludes` (`UnityCG.cginc`,
  `HLSLSupport.cginc`, `UnityShaderVariables.cginc`). Нужно имитировать то, что делает компилятор Unity: `#define`
  ключевые слова варианта, `SHADER_API_D3D11`, `UNITY_VERSION 201740` и т.п. Windows SDK (`fxc`) не установлен, но есть
  `C:\Windows\System32\d3dcompiler_47.dll` — `D3DCompile` можно звать через P/Invoke или NuGet (Vortice.Direct3D11 /
  Vortice.D3DCompiler). Отражение (`D3DReflect`) скомпилированного шейдера даст раскладку для сопоставления с оригиналом.
- **Не тестируй `fix_shaders.py`-специфичное как ошибку**: декларации `unity_ProbeVolume*` и `unity_Meta*` под
  `#if`, счётчики циклов `i`, `multi_compile` вместо `shader_feature` — это намеренные правки для gles3.
- **Допуски.** Порядок операций и fused multiply-add дают мелкие расхождения; сравнивай с относительным допуском,
  отдельно отмечай NaN/Inf и смену знака. Текстуры — 8-битные и float, с разной фильтрацией (point достаточно).
- **Детерминизм.** Фиксированный seed; при расхождении — сохранять входы, чтобы можно было воспроизвести.
- **Варианты.** Вариантов тысячи (у `Brave/LitBlendUber` десятки). Начни с шейдеров из списка ниже, потом — все.
- Инструмент — отдельный проект в `port/` (например, `port/ShaderDiff/`, .NET 9 как `Patcher`). Результат — отчёт
  (Markdown/HTML) в `port/build/shaderdiff/` или аналогичном месте, не в git. `.gitignore` — белый список: исходники
  инструмента добавь в `port/`, бинарники и отчёты — нет.

С чего начать (эти шейдеры уже проверены в игре и должны выйти **чистыми** — хороший контроль):
`Brave/Internal/GBuffer_LightRenderer_Fast`, `Brave/Internal/GBuffer_LightRenderer`, `Hidden/SENaturalBloomAndDirtyLens`,
`Brave/LitTk2dCustomFalloffTiltedCutout`, `Brave/PlayerShader`, `Custom/Shadow/Distance`.
Для проверки, что инструмент вообще ловит ошибки, временно откати одну из правок патча (например, `log2` → `log`) —
отчёт должен её показать.

## Ограничения

- Ничего не коммить и не публиковать без явной просьбы. Файлы игры и рип защищены авторским правом, проект приватный.
- Не трогай `C:\Program Files\Unity\...`.
- Если исправляешь найденные ошибки в USCSandbox — обнови `port/patches/uscsandbox-fixes.patch`
  (`git -C tools/src/USCSandbox diff --ignore-cr-at-eol > port/patches/uscsandbox-fixes.patch`), проверь, что он
  накладывается на чистый клон (`git apply --check --ignore-whitespace`), пересобери `tools/uscs`, прогони
  `decompile_shaders.sh` и `apply.sh` (`verify` — «All references resolve.»), допиши класс ошибки в README.
- Unity не всегда замечает изменённые файлы — проси пользователя нажать Ctrl+R. Лог Unity:
  `%LOCALAPPDATA%\Unity\Editor\Editor.log` — читай его сам.

## Критерии готовности

1. Инструмент собирается и запускается одной командой, прогоняет все декомпилированные шейдеры (или явно
   перечисляет, что пропущено и почему — например, нет DXBC для варианта).
2. Контрольные шейдеры выше — без расхождений; с откаченной правкой `log2` — расхождения находятся.
3. Отчёт: список расходящихся шейдеров/вариантов с примерами входов и выходов, сгруппированный по вероятной причине.
4. Найденные новые классы ошибок исправлены в USCSandbox (или описаны, если исправить нельзя), патч и README обновлены.
